3. ELECTRON MAIN PROCESS FEATURES
================================================================================

3.1 APP LIFECYCLE & WINDOW MANAGEMENT
  - GPU acceleration disabled (avoids Windows renderer crashes)
  - Chromium sandbox disabled
  - Software rendering forced
  - Autoplay policy set to 'no-user-gesture-required' (notification sounds)
  - Frameless window with custom titlebar (frame: false, titleBarStyle: 'hidden')
  - Window size: 1400x900 default, min 900x600
  - Context isolation enabled, node integration disabled
  - Renderer process crash handling: auto-reloads up to 2 times
  - Window state broadcasts: maximize/unmaximize events sent to renderer
  - macOS support: app stays open when all windows closed (window-all-closed handler)
  - External link handling: all new windows open in system browser
  - Clean shutdown: sync stops, Proton sessions destroyed on before-quit

3.2 SQLITE STORAGE SERVICE (src/main/services/storage.ts)
  Database: better-sqlite3, stored at app.getPath('userData')/mailbridge.db
  Tables:
    accounts — id, data (encrypted JSON), created_at, updated_at
    settings — key/value pairs with timestamps
    email_cache — account_id, message_id, thread_id, data, cached_at
    app_logs — id, timestamp, level, message, context
  WAL mode enabled, foreign keys enforced
  Account data: stored encrypted via EncryptionService
  Settings: merged with DEFAULT_SETTINGS on read
  Cache: per-account message caching with retrieval by ID or bulk
  Logging: persistent app logs with retention
  Export/Import: full data export (encrypted JSON blob) and import
  Generic key-value store: getKeyValue/setKeyValue/deleteKey

3.3 ENCRYPTION SERVICE (src/main/services/encryption.ts)
  Primary: Electron safeStorage (OS-level encryption tied to user account)
  Fallback: AES-256-GCM with file-based key in .mailbridge-key
  Encryption format prefix: 'ss:' for safeStorage, 'fk:' for file key
  Backward compatibility with legacy format (no prefix)
  Hash function using SHA-256
  canDecrypt() method for validation before attempting decryption

3.4 GMAIL AUTH SERVICE (src/main/services/gmail-auth.ts)
  PKCE OAuth flow with code verifier + challenge
  State parameter for CSRF protection
  Local HTTP callback server on random available port
  Duplicate account detection (same email across different account IDs)
  Token exchange via direct HTTP POST
  Token refresh: primary = direct HTTP POST, fallback = google-auth-library
  Retry with exponential backoff (3 retries, base 1s delay)
  Reauth error classification (GmailReauthRequiredError)
  Full account recovery (verify -> refresh -> recreate -> validate)
  Client reinitialization after errors
  OAuth status broadcast to renderer during auth flow
  Account validation (check token decryptability, expiry, refresh capability)
  Token encryption before storage

3.5 GMAIL API CLIENT (src/main/services/gmail-api-client.ts)
  Direct HTTP fetch to gmail.googleapis.com (replaces google-auth-library wrapper)
  Methods:
    listThreads — with Gmail query syntax support
    getThread — full thread with all messages parsed
    modifyThread — add/remove labels
    listLabels — all Gmail labels with counts
    sendMessage — MIME multipart/alternative (text + HTML)
    trashThread
    deleteThreadPermanently
    getMessage
    getAttachment
    getProfile
    getUnreadSnapshot — unread count + latest unread thread summaries
    healthCheck — lightweight profile API call
  Thread summary cache with 30-second TTL
  Concurrency limited metadata fetching (default 4 parallel)
  Rate limiting with exponential backoff + jitter (max 4 retries)
  Base64 decoding for email body parts (URL-safe variant)
  MIME body parsing: collects HTML, text, and attachments from multipart emails
  Thread-level operations (modify, trash, delete)

3.6 GMAIL CONNECTION STATE MANAGER (src/main/services/gmail-connection-state.ts)
  State machine per account: disconnected, initializing, initialized, ready, error, recovering
  Global readiness signal
  Per-account readiness promises
  Automatic recovery with retry on failure
  State change broadcasts to renderer via IPC
  Validation and cleanup of stale/corrupted accounts
  Health check with state update

3.7 GMAIL ERROR CLASSIFICATION (src/main/services/gmail-errors.ts)
  Error categories: reauth, transient, unknown
  Reauth errors: invalid_grant, invalid_token, 401/403, expired/revoked tokens
  Transient errors: rate limits (429), network errors, DNS, timeouts, 500/502/503
  Custom error classes: GmailReauthRequiredError, GmailTransientError
  Pattern matching for error message strings
  Functions: isGmailQuotaError, isGmailReconnectError, isTransientGmailNetworkError

3.7B GMAIL ERROR HELPERS (src/main/services/gmail-helpers.ts)
  Re-exports from gmail-errors.ts for backwards compatibility
  Dedicated functions:
    isGmailQuotaError — regex check for quota/rate-limit error messages
    isGmailPermanentDeleteReconnectMessage — detects "permanently delete Trash or Spam" error
    isGmailReconnectError — checks instanceof GmailReauthRequiredError or classifyGmailError === 'reauth'
    isTransientGmailNetworkError — checks classifyGmailError === 'transient'
